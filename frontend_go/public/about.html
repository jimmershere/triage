About us

Built by operators, engineers, and systems problem-solvers

Triage was built to solve a real operational problem: healthcare EDI systems are often brittle, opaque, difficult to troubleshoot, and overloaded with manual exception handling.

Instead of treating claims processing like a black-box transaction pipe, we approached it as a systems-engineering problem.

Who built it

The platform was designed and implemented by engineers with deep experience in:

  • enterprise infrastructure
  • systems integration
  • workflow automation
  • distributed processing
  • healthcare EDI operations
  • AI-assisted orchestration
  • production troubleshooting at scale

A large portion of the platform architecture, processing engine, validation framework, and AI workflow integration was designed and developed by Jim Kelley and his engineering collaborators.

Jim’s background spans infrastructure engineering, automation engineering, backend systems, workflow orchestration, and operational recovery in complex production environments. That experience heavily shaped the direction of Triage: practical systems first, observable behavior second, AI only where it adds measurable value.

What we built

Triage evolved from a traditional EDI workflow engine into a modern intelligent claims-processing platform capable of:

  • multi-tier healthcare claim routing
  • AI-assisted exception handling
  • X12 validation and transformation
  • real-time operational dashboards
  • CMS-grade transaction validation
  • FHIR interoperability
  • swarm-based supervised AI workloads
  • visual transaction mapping and debugging

The architecture combines:

  • Python processing pipelines
  • Go frontend systems
  • PostgreSQL operational storage
  • RabbitMQ workflow orchestration
  • X12 transaction engines
  • supervised AI agent workflows
  • structured auditability and replay systems

Major platform components completed

Tiered AI claim routing engine

One of the platform’s core systems is a multi-tier intelligent routing architecture that dynamically classifies healthcare claims based on complexity, risk, anomaly detection, and confidence scoring.

The routing system supports:

  • deterministic low-cost processing paths
  • escalation workflows
  • supervised AI review
  • human exception handling
  • persistent routing audit trails

The platform currently supports Tier 0 through Tier 3 processing workflows, including supervised swarm-based AI review pipelines.

CMS-grade validation framework

We implemented a healthcare validation engine covering:

  • WEDI SNIP 1–7 validation
  • HIPAA transaction compliance
  • 837P / 837I / 837D support
  • 835 / 270 / 271 / 276 / 277 / 278 transaction support
  • TA1, 999, and 277CA acknowledgment generation

The engine includes:

  • positioned segment-aware parsing
  • rule-driven validation
  • issue anchoring
  • standards-aware transaction analysis

The roadmap and implementation now include over 200 automated tests validating platform behavior.

Visual X12 mapping and canvas system

We designed and implemented a canvas-based visual transaction mapper capable of:

  • interactive X12 segment visualization
  • contextual issue highlighting
  • schema-aware transaction rendering
  • guided troubleshooting overlays
  • positioned validation issue reporting

This dramatically improves observability and troubleshooting compared to legacy EDI tooling.

Real-time exception command center

Triage includes a command-center architecture designed for operational teams managing claim exceptions at scale.

The system aggregates:

  • denial severity
  • financial exposure
  • category breakdowns
  • queue prioritization
  • operational risk metrics

The dashboard architecture supports operator, analyst, and executive-level workflows simultaneously from a unified data model.

AI-guided remediation and supervised swarms

A major focus of the platform has been supervised AI orchestration rather than unsupervised automation.

We implemented:

  • denial-resolution swarms
  • remediation suggestion systems
  • supervised verdict workflows
  • structured audit trails
  • confidence-scored escalation
  • retry-safe orchestration frameworks

The swarm framework records prompts, responses, retries, timing, and decision audit history for compliance replay and operational transparency.

Engineering philosophy

Reliability over hype

AI is used selectively where it improves operational outcomes, not as a replacement for deterministic systems.

Observability first

Operators should be able to understand why a claim failed, where a transaction broke, why a routing decision occurred, what the AI concluded, and how remediation was suggested.

Human-supervised AI

The system is designed around escalation, auditability, replay, and controlled workflows—not black-box automation.

Practical interoperability

FHIR and X12 interoperability were treated as operational requirements, not marketing features.

Where we’re going

The next phase of Triage focuses on scaling the platform into a fully operational intelligent healthcare workflow ecosystem.

Current and future initiatives include:

  • expanded FHIR interoperability
  • production-grade payer integrations
  • live eligibility and claim-status orchestration
  • advanced denial-prediction workflows
  • enhanced operational dashboards
  • large-scale workflow automation
  • compliance-aware AI orchestration
  • real-time financial risk analysis
  • advanced healthcare workflow intelligence

Long-term, the goal is to build a modern healthcare operations platform that combines deterministic processing, AI-assisted orchestration, human-guided decision systems, transparent operational intelligence, and scalable workflow infrastructure—without sacrificing reliability, auditability, or operator control.

Our perspective

Healthcare EDI infrastructure has historically been dominated by opaque systems, brittle integrations, and difficult operational workflows.

Triage was built differently.

The goal was never simply to process transactions. The goal was to build a platform that helps operators understand, manage, prioritize, repair, route, and improve healthcare workflow systems in real time—using modern engineering practices, observable architecture, and carefully supervised AI systems.
